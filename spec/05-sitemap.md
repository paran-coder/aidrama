# 정보구조와 사이트맵

## 영역 구분
마케팅 영역(비로그인 진입)과 앱 영역(로그인 후 사용)으로 구분. 별도 운영/관리자 화면은 `/admin` 하나로 최소화한다 (본인 1인만 사용).

## 내비게이션 구조

| 영역 | 항목 |
|---|---|
| 글로벌 내비게이션 (로그인 후) | 내 챌린지, 전체 현황, 마이페이지 |
| 유틸리티 | 알림, 로그인/로그아웃 |
| 푸터 | 서비스 소개, 챌린지 규칙 안내, 문의 |

## 사이트맵

```
/ (랜딩) ─────────────────── 마케팅. 서비스 소개 + 챌린지 규칙 + 참여 유도
├── /login ──────────────── 로그인
├── /signup ─────────────── 회원가입 (초대 코드 입력 필수, 1코드-1인 매칭)
│
├── /onboarding ─────────── 챌린지 시작 (알 등록, 경과일 시작) — 최초 1회
│
├── /dashboard ──────────── 내 챌린지 (기본 진입 화면, 로그인 후)
├── /dashboard/submit ───── 이번 주 업로드 링크 제출
├── /dashboard/history ──── 내 업로드·실패 이력
│
├── /community ──────────── 전체 참여자 현황
│   └── /community/:userId  다른 사용자의 부엉이 프로필
│
├── /mypage ─────────────── 계정 설정
├── /complete/:userId ───── 1000일 완주 아카이브
│
└── /admin ──────────────── 관리자 전용 (본인만 접근)
    └── 초대 코드 발급/목록/사용 현황
```

## 결정 / 근거 / 가정

- **결정**: `/signup`은 초대 코드 없이는 진행 불가
  **근거**: 모집형 서비스 요구사항을 게이트키핑으로 강제
- **결정**: 관리자 계정은 본인 1인만 소유, 별도 관리자 초대 기능 없음
- **결정**: 초대 코드는 1코드-1인 매칭, 1회 사용 후 만료
- **가정**: 최초 관리자 계정은 환경변수 또는 시드 데이터로 생성

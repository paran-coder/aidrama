# 화면별 상세 명세

# S01 대시보드 (`/dashboard`)

## 목적
사용자가 로그인 직후 가장 먼저 보는 화면으로, 현재 챌린지 진행 상태(부엉이 성장 단계, 경과일, 스트릭)를 한눈에 파악하고 이번 주 제출로 이어지게 한다.

## 대상 사용자 / 진입 조건
챌린지를 시작한(onboarding 완료) 로그인 사용자. 온보딩 미완료 시 `/onboarding`으로 리다이렉트.

## 사용자가 답을 얻어야 하는 질문
지금 내 부엉이는 어떤 상태인가? 이번 주 제출을 아직 안 했나? 지금 위험한 상태인가?

## 콘텐츠 우선순위
1. 부엉이 성장 시각화 (현재 단계)
2. 스트릭 / 경과일 ("n일 연속", "1000일 중 n일째")
3. 이번 주 제출 여부 및 제출 버튼
4. 경고 상태 알림(해당 시)

## 주요 행동
이번 주 업로드 링크 제출 (`/dashboard/submit`로 이동)

## 보조 행동
이력 보기(`/dashboard/history`), 전체 현황 보기(`/community`)로 이동

## 데이터와 출처
- 부엉이 성장 단계: 서버에서 계산된 현재 단계(경과일 + 연속실패 반영 결과)
- 스트릭: 연속 성공 주차 수
- 경과일: 챌린지 시작일 기준 오늘까지 일수 (1000일 상한)
- 연속실패 횟수: 경고 팝업 노출 여부 판단용

## 상태와 예외
- Default: 정상 진행 중, 이번 주 제출 전
- Empty: 해당 없음
- Loading: 성장 상태 데이터 로딩 중 (스켈레톤)
- Error: 데이터 조회 실패 (재시도 안내)
- Permission: 온보딩 미완료 → `/onboarding` 리다이렉트
- Success: 이번 주 제출 완료 상태 표시
- 연속실패 2회(경고): 진입 시 팝업 노출

## 반응형 동작
모바일에서는 부엉이 시각화와 제출 버튼을 우선 노출하고, 이력/커뮤니티 진입 링크는 하단으로 축약.

## 접근성 요구
경고 팝업은 스크린리더가 인식 가능한 alert 역할로 제공, 키보드만으로 닫기 가능.

## 분석 이벤트
`dashboard_view`, `warning_popup_shown`, `submit_button_click`

## 다음 화면 / 이탈 경로
제출 버튼 → `/dashboard/submit` / 이력 → `/dashboard/history` / 커뮤니티 → `/community`

## 수용 기준
- [ ] 경과일과 스트릭이 정확히 계산되어 표시된다
- [ ] 연속실패 2회 도달 시 팝업이 노출된다
- [ ] 이번 주 이미 제출했으면 제출 버튼이 완료 상태로 바뀐다
- [ ] 온보딩 미완료 사용자는 자동으로 `/onboarding`으로 이동한다

# S02 업로드 제출 (`/dashboard/submit`)

## 목적
사용자가 이번 주 SNS 업로드 링크를 제출하고, 자동 검증을 거쳐 성공/미검증 상태로 기록되게 한다.

## 대상 사용자 / 진입 조건
챌린지 진행 중이며 아직 이번 주 제출을 하지 않은 로그인 사용자. `/dashboard`에서 진입.

## 사용자가 답을 얻어야 하는 질문
링크를 어떻게 제출하나? 제출이 잘 됐는지 어떻게 아나? 실패하면 어떻게 되나?

## 콘텐츠 우선순위
1. 링크 입력 필드
2. 제출 마감까지 남은 시간(일요일 23:59 기준)
3. 검증 상태 안내
4. 제출 후 다음 행동 안내

## 주요 행동
링크 입력 후 제출

## 보조 행동
검증 실패 시 재시도, 대시보드로 돌아가기

## 데이터와 출처
- 제출 링크 URL
- 제출 시각 (마감 기준 판정용)
- 검증 결과(성공/미검증) — 외부 플랫폼 API 또는 링크 형식 검사 결과

## 상태와 예외
- Default: 링크 입력 전
- Empty: 해당 없음
- Loading: 자동 검증 진행 중
- Error: 유효성 오류(잘못된 링크 형식), 네트워크 오류
- Permission: 이미 이번 주 제출 완료 → 중복 제출 차단
- Success: 검증 성공 시 "검증됨" 배지, 검증 실패 시 "미검증"으로 자동 인정 + 재시도 버튼 제공

## 반응형 동작
모바일에서는 입력창과 제출 버튼을 화면 상단에 고정 배치.

## 접근성 요구
검증 중 로딩 상태를 스크린리더에 안내(aria-live), 오류 메시지는 입력 필드와 명확히 연결.

## 분석 이벤트
`submit_attempt`, `submit_verified`, `submit_unverified`, `submit_duplicate_blocked`

## 다음 화면 / 이탈 경로
제출 완료 → `/dashboard`로 자동 이동

## 수용 기준
- [ ] 마감 시각(일요일 23:59) 이후 제출은 다음 주차로 처리되지 않고 실패로 기록된다
- [ ] 이미 제출한 경우 재제출이 차단된다
- [ ] 자동 검증 실패 시 제출은 인정되고 "미검증" 배지가 표시된다
- [ ] 검증 실패 시 재시도 버튼이 노출된다

# S03 회원가입 (`/signup`)

## 목적
초대 코드를 가진 사용자만 계정을 생성할 수 있도록 게이트키핑하며 가입을 완료시킨다.

## 대상 사용자 / 진입 조건
초대 코드를 받은 신규 사용자. 랜딩 또는 초대 링크를 통해 진입.

## 사용자가 답을 얻어야 하는 질문
초대 코드가 없으면 가입할 수 없나? 코드가 맞는지 어떻게 확인하나?

## 콘텐츠 우선순위
1. 초대 코드 입력
2. 이메일/비밀번호(또는 소셜 로그인) 입력
3. 가입 완료 후 안내

## 주요 행동
초대 코드 + 계정 정보 입력 후 가입

## 보조 행동
로그인 화면으로 이동(이미 계정이 있는 경우)

## 데이터와 출처
- 초대 코드 유효성(존재 여부, 미사용 여부) — 서버 검증
- 계정 정보(이메일 등)

## 상태와 예외
- Default: 입력 전
- Empty: 해당 없음
- Loading: 코드 검증 중
- Error: 코드 오류(존재하지 않음 / 이미 사용됨), 계정 정보 유효성 오류(중복 이메일 등)
- Permission: 해당 없음
- Success: 가입 완료 → `/onboarding`으로 이동

## 반응형 동작
단일 컬럼 폼으로 모바일/데스크톱 동일하게 표시.

## 접근성 요구
코드 오류 메시지는 입력 필드와 명확히 연결, 포커스가 오류 필드로 자동 이동.

## 분석 이벤트
`signup_attempt`, `signup_code_invalid`, `signup_success`

## 다음 화면 / 이탈 경로
가입 성공 → `/onboarding` / 이미 계정 있음 → `/login`

## 수용 기준
- [ ] 초대 코드가 없으면 가입이 진행되지 않는다
- [ ] 사용된 코드로는 재가입이 불가능하다
- [ ] 가입 성공 시 해당 코드는 즉시 사용 처리되어 다른 사람이 재사용할 수 없다

# S04 로그인 (`/login`)

## 목적
기존 사용자가 계정으로 접속해 자신의 챌린지 진행 상황에 접근하게 한다.

## 대상 사용자 / 진입 조건
이미 가입된 사용자. 랜딩 또는 세션 만료 후 진입.

## 사용자가 답을 얻어야 하는 질문
내 계정으로 맞게 들어왔나? 비밀번호를 잊었으면 어떻게 하나?

## 콘텐츠 우선순위
1. 로그인 입력 폼
2. 비밀번호 찾기 링크
3. 회원가입 안내(계정 없는 경우)

## 주요 행동
로그인

## 보조 행동
비밀번호 재설정, 회원가입으로 이동

## 데이터와 출처
계정 인증 정보 (이메일/비밀번호 또는 소셜 로그인 토큰)

## 상태와 예외
- Default: 입력 전
- Empty: 해당 없음
- Loading: 인증 처리 중
- Error: 잘못된 인증 정보, 네트워크 오류
- Permission: 해당 없음
- Success: 로그인 성공 → `/dashboard`로 이동 (관리자 계정이면 `/admin` 진입도 가능)
- 세션 만료 후 재접속: "세션이 만료되었습니다" 안내와 함께 로그인 폼 노출

## 반응형 동작
단일 컬럼 폼, 모바일/데스크톱 동일.

## 접근성 요구
오류 메시지는 입력 필드와 연결되고 스크린리더가 읽을 수 있어야 함.

## 분석 이벤트
`login_attempt`, `login_failed`, `login_success`

## 다음 화면 / 이탈 경로
성공 → `/dashboard` / 계정 없음 → `/signup`

## 수용 기준
- [ ] 잘못된 인증 정보 입력 시 명확한 오류 메시지가 표시된다
- [ ] 세션 만료 후 재접속 시 이전 페이지로 복귀 가능하다

# S05 온보딩 (`/onboarding`)

## 목적
가입 직후 챌린지를 실제로 "시작"시키는 화면으로, 부엉이를 알 상태로 등록하고 경과일을 시작시킨다.

## 대상 사용자 / 진입 조건
가입은 완료했지만 아직 챌린지를 시작하지 않은 사용자. 가입 직후 자동 진입, 또는 `/dashboard` 접근 시 미완료 상태면 리다이렉트.

## 사용자가 답을 얻어야 하는 질문
챌린지가 정확히 언제부터 시작되나? 규칙이 뭔가?

## 콘텐츠 우선순위
1. 챌린지 규칙 요약 (매주 제출, 실패 시 페널티, 1000일 목표)
2. 시작하기 버튼
3. 알 상태 부엉이 소개

## 주요 행동
"챌린지 시작하기" 버튼 클릭

## 보조 행동
규칙 다시 보기

## 데이터와 출처
챌린지 시작일. 경과일은 버튼 클릭 즉시 0일차로 시작하고, 주간 판정은 가입한 주를 제외하고 다음 월요일부터 시작한다.

## 상태와 예외
- Default: 시작 전 안내 화면
- Empty: 해당 없음
- Loading: 시작 처리 중
- Error: 처리 실패(재시도 안내)
- Permission: 이미 챌린지 시작한 사용자가 접근 시 `/dashboard`로 리다이렉트
- Success: 시작 완료 → `/dashboard`로 이동

## 반응형 동작
단일 컬럼, 규칙 텍스트는 모바일에서 접기/펼치기로 축약 가능.

## 접근성 요구
시작 버튼은 명확한 레이블과 충분한 터치 영역을 가져야 함.

## 분석 이벤트
`onboarding_view`, `challenge_started`

## 다음 화면 / 이탈 경로
시작 완료 → `/dashboard`

## 수용 기준
- [ ] 시작 버튼 클릭 시 경과일 0일차가 서버에 정확히 기록된다
- [ ] 이미 시작한 사용자는 이 화면에 재진입할 수 없다
- [ ] 첫 주간 판정은 가입 주를 제외하고 다음 월요일부터 시작된다

# S06 전체 현황 (`/community`)

## 목적
다른 참여자들의 진행 상황을 보여줘 서로 자극과 동기부여가 되게 한다.

## 대상 사용자 / 진입 조건
챌린지 진행 중인 로그인 사용자.

## 사용자가 답을 얻어야 하는 질문
다른 사람들은 얼마나 잘하고 있나? 나는 상대적으로 어디쯤인가?

## 콘텐츠 우선순위
1. 참여자 목록 (부엉이 성장 단계 썸네일 + 스트릭)
2. 정렬 기준 (기본: 최장 스트릭순 — 가정)
3. 본인 위치 하이라이트

## 주요 행동
다른 참여자 프로필 클릭 → `/community/:userId`

## 보조 행동
정렬 기준 변경(있다면)

## 데이터와 출처
전체 참여자의 부엉이 단계, 스트릭, 경과일 (공개 범위는 전체 공개로 가정)

## 상태와 예외
- Default: 참여자 목록 표시
- Empty: 본인 외 참여자 없음
- Loading: 목록 로딩 중
- Error: 조회 실패
- Permission: 해당 없음(로그인 사용자면 누구나 열람 가능으로 가정)
- Success: 해당 없음

## 반응형 동작
모바일에서는 그리드 대신 리스트형으로 전환.

## 접근성 요구
목록 항목은 키보드로 순차 접근 가능해야 함.

## 분석 이벤트
`community_view`, `community_profile_click`

## 다음 화면 / 이탈 경로
프로필 클릭 → `/community/:userId`

## 수용 기준
- [ ] 모든 참여자의 현재 상태가 실시간에 가깝게 반영된다
- [ ] 본인 카드가 시각적으로 구분된다

# S07 다른 사용자 프로필 (`/community/:userId`)

## 목적
특정 참여자의 진행 상황을 상세히 보여줘 구체적인 자극과 응원 포인트를 제공한다.

## 대상 사용자 / 진입 조건
로그인 사용자, `/community`에서 프로필 클릭 시 진입.

## 사용자가 답을 얻어야 하는 질문
이 사람은 며칠째 하고 있나? 몇 번 실패했나?

## 콘텐츠 우선순위
1. 부엉이 성장 시각화(일자별)
2. 스트릭 / 경과일
3. (Should 항목 채택 시) 응원 버튼

## 주요 행동
목록으로 돌아가기

## 보조 행동
(Should 채택 시) 응원 남기기

## 데이터와 출처
해당 사용자의 성장 단계, 스트릭, 경과일 (공개 데이터로 가정)

## 상태와 예외
- Default: 프로필 표시
- Empty: 해당 없음
- Loading: 로딩 중
- Error: 조회 실패
- Permission: 존재하지 않는 userId → 404 안내
- Success: 해당 없음

## 반응형 동작
단일 컬럼, 모바일 우선 레이아웃.

## 접근성 요구
이미지(부엉이 성장 시각화)에 대체 텍스트를 제공.

## 분석 이벤트
`profile_view`

## 다음 화면 / 이탈 경로
뒤로가기 → `/community`

## 수용 기준
- [ ] 존재하지 않는 사용자 접근 시 404 화면이 표시된다

# S11 관리자 초대 코드 (`/admin`)

## 목적
관리자(본인)가 초대 코드를 발급하고 사용 현황을 확인하게 한다.

## 대상 사용자 / 진입 조건
관리자 권한을 가진 계정만 접근. 일반 사용자는 접근 불가.

## 사용자가 답을 얻어야 하는 질문
코드를 몇 개 발급했나? 누가 어떤 코드로 가입했나?

## 콘텐츠 우선순위
1. 코드 발급 버튼
2. 발급된 코드 목록(사용 여부 표시)
3. 코드별 사용자 매칭 현황

## 주요 행동
새 초대 코드 발급

## 보조 행동
코드 목록 조회

## 데이터와 출처
발급된 코드 목록, 각 코드의 사용 여부 및 사용한 사용자 정보

## 상태와 예외
- Default: 코드 목록 표시
- Empty: 발급된 코드 없음
- Loading: 발급/조회 처리 중
- Error: 발급 실패
- Permission: 일반 사용자 접근 시 → 403 또는 대시보드로 리다이렉트
- Success: 발급 완료 안내

## 반응형 동작
본인만 사용하는 화면이라 데스크톱 우선으로 설계해도 무방.

## 접근성 요구
표 형태 목록은 스크린리더로 순차 탐색 가능해야 함.

## 분석 이벤트
없음(내부 관리 화면이라 분석 불필요로 가정)

## 다음 화면 / 이탈 경로
해당 없음(관리자 전용 허브)

## 수용 기준
- [ ] 관리자가 아닌 계정으로는 접근할 수 없다
- [ ] 발급된 코드는 1회 사용 후 자동으로 사용 완료 처리된다
